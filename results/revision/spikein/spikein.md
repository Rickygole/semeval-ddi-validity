# Spike-in sensitivity calibration

Post hoc and exploratory; it changes no preregistered decision. Criteria were fixed in `criteria.json` before any run.

Synthetic scores on the frozen rows: s = w * rank(DrugBank lookup, random tie-break) + (1 - w) * (rank(base) + 0.1 * z), w calibrated so the realised within-drug kappa (against the real DrugBank within-drug AUROC of the same rows) matches the target in expectation. Each rep goes through the H1 pipeline: within-drug AUROC, two-way cluster bootstrap (300 draws, seed 42 Older, 1042 Novel), 90% and 95% percentile intervals, p_TOST, decision. 200 reps per grid point.

Rules. AUROC rule (H1): equivalent if the 90% interval is inside (0.40, 0.60), falsified if the 95% lower bound is above 0.60. Holm: evaluate2.decide_equivalence with Holm over H1, H4 = 0.3387, H6 = 0.1019. Kappa rule: equivalent if the paired kappa 95% upper bound is at most 0.25, falsified if its 95% lower bound is above 0.25. Detected: within-drug AUROC 95% lower bound above 0.50.

Deviation from criteria.json, decided after a smoke run with tiny settings and before the full run: the criteria flag a target outside the calibration curve as unreachable. Monte Carlo error put the exact endpoints (kappa 1 at w = 1 for both bases, kappa 0 at w = 0 for the noise base) a hair outside the curve, so a target within 3 Monte Carlo standard errors of an endpoint is set to that endpoint; each job lists the targets this affected. On Novel the b2mixed base already has kappa about 0.10 at w = 0, so its targets 0 and 0.05 are unreachable and were not run; the noise base covers them.

Tier B note: the DrugBank lookup agrees with the label on every tier B row by construction, so its tier B ceiling is 1.000 and tier B kappa is on a different scale; the x axis stays the tier A target.
